# BMS Web Monitor & Diagnostics (`tools/bms_web.py`, v3.6)

Локальна веб-станція моніторингу, інженерної діагностики та CSV-логування для банку акумуляторів **Vision V-LFP48100** (до 16 паралельних блоків).  
Працює на **Python 3** (`pyserial` потрібен лише для живого COM-порту); інтерфейс і графіки побудовані на Vanilla JS / HTML5 Canvas без зовнішніх JS-бібліотек або доступу до інтернету.

> Цей документ є єдиною актуальною інструкцією для `tools/bms_web.py` і консолідує матеріали щодо інтерфейсу, історії функціоналу v2.4–v3.6 та механізму CSV-логування.

---

## 1. Основні можливості (v3.6)

### Підключення, стійкість та UX
- **Smart USB/COM автопошук і reconnect:** автоматичне визначення адаптера RS485-USB із коректним відновленням зв'язку після коротких збоїв або перепідключення кабелю.
- **Чітке розрізнення `No Dongle` та `OFFLINE`:** при втраті адаптера або тайм-ауті блоків UI очищує застарілі значення та не показує «заморожену» стару телеметрію як живу.
- **Автономний запуск (`--allow-no-port`):** дозволяє відкрити веб-інтерфейс без фізичного RS485-донгла — насамперед для **Офлайн-аналізатора CSV-логів**, калькулятора уставок та інспектора DIP-перемикачів.
- **Захист подвійного кліку (`_launched_from_explorer` / `_pause_if_double_click`):** при запуску подвійним кліком консоль не закривається миттєво при помилці чи завершенні; для автоматизації пауза вимикається змінною `BMS_NO_PAUSE=1`.

### Діагностика батарейного банку
- **Мульти-паковий моніторинг (адреси `1..16`):** сумарна шина банку (`Voltage_V`, `Current_A`, `Power_W`, `SOC_pct`, `SOH_pct`) і повна телеметрія кожного блоку.
- **Монітор комірок `Cell 1..15` і **Pack Balance Inspector**:** відображення `Cell_Min_V`, `Cell_Max_V`, розбіжності `Cell_Diff_V`, бітової маски балансування `Balance_Hex`, виявлення слабких комірок (**Weak Cell**) та оцінка внутрішнього опору ($R_{int}$).
- **Коректне розділення температур (`Temp PCB` vs `Temp 1..6`):** температура плати BMS (`Temp_PCB_C`) відокремлена від датчиків комірок і не спотворює `Temp_Avg_C` / `Temp_Max_C`.
- **Калькулятор уставок інвертора (Deye CAN / RS485):** розрахунок параметрів заряду/розряду та контрольна перевірка конфігурації банку.
- **Модальне вікно `DIP 1..5`:** візуальний конфігуратор і підказчик адресних та режимних перемикачів.
- **Інтерактивний Alarm Helper:** розшифрування регістрів `Status_Hex`, `Warning_Hex`, `Protection_Hex`, `Error_Hex`, зокрема:
  - `Status 0025`: `Standby (0x00)`, `Charging (0x01)`, `Discharging (0x02)`, `Protect (0x04)`, `Charging Lmt (0x08)`, `Heating ON (0x8000)`;
  - попередження `Float stop (0x1000)` та прапор `Reverse (0x4000)`.
- **Графіки (HTML5 Canvas) та A4 PDF-звіт:** побудова трендів напруги/струму/комірок/температур і генерація друкованого A4-паспорта стану банку.
- **Офлайн-аналізатор логів:** розбір раніше збережених CSV-файлів прямо у браузері.

## 2. Механізм CSV-логування (v3.5 / v3.6)

Система логування записує події та періодичні зрізи телеметрії у два потоки (робочий і аварійний журнали, зокрема `bms_bank_log.csv` і `bms_alarm_log.csv`) із єдиною впорядкованою схемою колонок `log_columns()`.

### Типи записів (колонка `Log`)
| Значення `Log` | Константа | Коли створюється | Призначення |
| :--- | :--- | :--- | :--- |
| **`Alarm`** | `LOG_KIND_ALARM` | Поява/зняття попереджень (`Warning_Hex`), захистів (`Protection_Hex`), помилок (`Error_Hex`), перегрів (`Temp >= 45.0 °C`, `ALARM_TEMP_HIGH_C`) або переохолодження (`Temp <= 0.0 °C`, `ALARM_TEMP_LOW_C`). | Негайна фіксація критичних і позаштатних подій без очікування робочого інтервалу. |
| **`State`** | `LOG_KIND_STATE` | Зміна робочого стану або прапорів (`Status_Hex`: Standby, Charging, Discharging, Protect, Charging Lmt, Heating ON тощо). | Відстеження переходів режимів роботи банку. |
| **`Work`** | `LOG_KIND_WORK` | Періодично за таймером (`DEFAULT_WORK_INTERVAL_S = 5.0` с; налаштовується в межах `1.0..3600.0` с). | Фоновий телеметричний ряд для графіків і оцінки деградації/балансування. |

### Гарантований порядок запису та колонка `Changes`
- **Порядок при однаковій мітці часу:** записи в межах одного циклу опитування пишуться строго у послідовності **`Alarm` → `State` → `Work`**, щоб аварійний тригер завжди передував зміні стану та плановому телеметричному рядку.
- **Колонка `Changes` (дельта за цикл):** формує компактний диференціал змін у рядках `Alarm` і `State`, наприклад:
  `W: 0x0000->0x0002; P: 0x1000->0x0000; S: 0x0004->0x0001; T: normal->high`  
  У рядках `Work` колонка `Changes` залишається порожньою.

### Повна схема колонок CSV (`log_columns()`)
Порядок колонок жорстко фіксований єдиним джерелом істини `log_columns()`:

1. `Date`, `Log`, `addr`
2. `Voltage_V`, `Current_A`, `Power_W`, `SOC_pct`, `Cap_Remaining_Ah`, `SOH_pct`, `Max_Charge_A`, `Cycles`, `Full_Capacity_Ah`, `Designed_Cap_Ah`
3. `Cell_Num`, `Cell_Min_V`, `Cell_Max_V`, `Cell_Diff_V`
4. `Temp_PCB_C`, `Temp_Avg_C`, `Temp_Max_C`
5. `Cell_1_V` .. `Cell_15_V`
6. `Temp_1_C` .. `Temp_6_C`
7. `Status_Hex`, `Warning_Hex`, `Protection_Hex`, `Error_Hex`, `Balance_Hex`, `Serial`
8. `Changes`

## 3. Швидкий старт та команди

```bash
# Встановлення залежності для роботи з реальним USB-RS485 адаптером
pip3 install pyserial

# Стандартний запуск (автопошук COM-порту та блоків 1..16)
python3 tools/bms_web.py

# Запуск без фізичного адаптера (офлайн-аналізатор, калькулятор, DIP-підказки)
python3 tools/bms_web.py --allow-no-port

# Запуск без паузи консолі при виході (корисно в скриптах/терміналі Windows)
BMS_NO_PAUSE=1 python3 tools/bms_web.py

# Вбудована самоперевірка протоколу, розрахунків і CSV-логіки без заліза
python3 tools/bms_web.py --selftest

# Повний перелік прапорців командного рядка
python3 tools/bms_web.py --help
```

## 4. Правила безпеки (Hardware Safety & Read-Only)

- **Strictly Read-Only на шині RS485:** `tools/bms_web.py` опитує BMS виключно функцією читання регістрів Modbus RTU (`FC 0x03`) і **ніколи не записує** уставки у BMS чи інвертор.
- **Запобігання колізіям на активній шині:** не підключайте активний майстер-опитувач паралельно до вже працюючого COMBOX або інвертора на тій самій півдуплексній лінії RS485. Для пасивного прослуховування трафіку без жодного байта на передачу використовуйте:
  - [`tools/rs485_sniff.py`](rs485_sniff.py) — пасивний RS485-сніфер;
  - [`tools/can_sniff.py`](can_sniff.py) — пасивний CAN-сніфер.
- **Критичні пороги LiFePO4 (контролюються прошивкою BMS):** Cell OVP `3.65 В`, Cell UVP `2.50 В`, температурна заборона заряду `< +2 °C`. Деталі протоколу та аварій описані у [`../VISION_BMS_PROTOCOL.md`](../VISION_BMS_PROTOCOL.md) та [`../SAFETY_AND_ALARMS.md`](../SAFETY_AND_ALARMS.md).

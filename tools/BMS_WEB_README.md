# BMS Web Monitor — веб-монітор акумулятора Vision (tools/bms_web.py)

**Версія:** v1.2 (22.10.2026) · **Стан:** читання (read-only), повністю робочий
Локальний веб-додаток для macOS (або будь-якої системи з Python) — аналог
Windows-програми **BMS_TOOLS_2.2.01** для нашого банку Vision V-LFP48100 через
RS485-тап.

---

## Що робить

Опитує **один пак** акумулятора по RS485 (Modbus RTU, запит `FC03 addr qty=39` —
той самий, що шле наша коробка і BMS_TOOLS) і показує все у браузері на
локальній сторінці. Паралельно може писати сирий лог у CSV.

**Два режими (v1.2, 22.10.2026):**
* **Активний** (типово) — власний опит `qty=39`, усі 39 регістрів. Лише коли
  шина вільна (інвертор/коробка не опитують — інакше колізії).
* **Пасивний** (`--passive`) — **нуль передач**: парсимо власний трафік
  інвертора (`qty=28`, реги 0–27 + вікно `0x50`). Працює при живій системі.
  Поза вікном інвертора (реги 28–38: Error, цикли, Full Capacity, Temp01–04,
  баланс, номінал) — на сторінці показується «—». Сторінка також показує,
  які адреси паків інвертор зараз бачить («бачить: 0x01 0x02 …»), а CSV-лог
  пише **усі бачені паки** (по рядку на пак у кожному скані).

**Сторінка:** `http://127.0.0.1:8080` (порт змінюється параметром `--http`)

### Розділи на сторінці

| Розділ | Джерело даних | Що показує |
|---|---|---|
| Живлення | reg 0, 1, 24, 23, 21, 22, 29/30, 31/32, 37 | напруга (В), струм (А), стан (pill), SOC (%) / Cap Remaining (А·ч), SOH / Max charge, цикли, номінал (А·ч, к-сть S), **Full Capacity (А·ч, з reg 31/32)** |
| Комірки | reg 2–17, 36 | усі 15 комірок у мВ, **Δ**, мін — червоною рамкою, макс — зеленою |
| Температури | reg 18/19/20 + 33–35 | PCB / Avg / Max °C + **Temp01–04 °C** (4 байти з «6 сенсорів» 0033–0035) |
| Status (0025) | reg 25 = r19 | LED: Charging, Discharging, Protect, Charging Lmt, Heating ON — **енум у нижньому байті (0/1/2/4/8) + нагрів 0x8000**; сирий hex у заголовку |
| Warning (0026) | reg 26 = r1A | 14 LED: Pack/Cell OV/UV, Charge/Discharge OC/OT/UT, Temp anomaly, MOS OT, Low capacity, Float stopped; сирий hex у заголовку |
| Protection (0027) | reg 27 = r1B | 15 LED: ті самі 0x0001–0x1000 + **0x2000 = Discharge SC**, **0x4000 = Reverse** (15-й LED з BMS_TOOLS); сирий hex |
| Error (0028) | reg 28 | Voltage / Temperature / Current sensor / Cell unbalance (4 біти: 01/02/04/10) + сирий hex |
| Balance (0038) | reg 38 | по-коміркові біти балансування (1–15) |
| CSV-лог | — | кнопка Старт/Стоп → кожне опитування = рядок у CSV-файл |

Статус зв'язку — пігулка у куті: **ONLINE 0xNN** (зелена) / **OFFLINE** (червона
+ текст помилки). Оновлення сторінки — раз на с, дані з сервера — кожні 0.35 с.

## Вимоги

- Python 3.9+;
- **pySerial** (`pip3 install pyserial`) — та сама залежність, що й у
  `tools/rs485_sniff.py`;
- USB-UART тап **FT232** (`--port /dev/cu.usbserial-A5069RR4` — дефолт;
  список портів: `python3 tools/bms_web.py --list`).

Більше жодних залежностей — HTML/JS вбудовані у скрипт, зовнішні файли не
потрібні.

## Запуск

```bash
# 1. Живий пак (типово addr 0x01):
python3 tools/bms_web.py --port /dev/cu.usbserial-A5069RR4

# 2. Конкретний пак (наприклад 0x02):
python3 tools/bms_web.py --port /dev/cu.usbserial-A5069RR4 --addr 0x02

# 3. Демо-режим без апаратури (фейкові дані, для перевірки сторінки):
python3 tools/bms_web.py --mock

# 3б. Пасивний режим — при працюючому інверторі (жодної передачі):
python3 tools/bms_web.py --port /dev/cu.usbserial-A5069RR4 --passive

# 4. Самоперевірка (CRC-вектори з живих логів + парсер пасивного режиму):
python3 tools/bms_web.py --selftest

# 5. Список серійних портів:
python3 tools/bms_web.py --list
```

Після запуску у консолі:

```
BMS web monitor: http://127.0.0.1:8080  [/dev/cu.usbserial-A5069RR4 @ 9600]  addr=0x01  (Ctrl-C to stop)
```

Відкрити **`http://127.0.0.1:8080`** у браузері. Зупинка — Ctrl-C у консолі.

### Параметри

| Параметр | Дефолт | Що робить |
|---|---|---|
| `--port` | `/dev/cu.usbserial-A5069RR4` | серійний порт тапа |
| `--baud` | `9600` | швидкість (Vision = 9600 8N1) |
| `--addr` | `0x01` | адреса пака (десятково або `0xNN`); 0x01–0x0F = модулі, 0x10 = master-пак |
| `--http` | `8080` | порт веб-сторінки (127.0.0.1) |
| `--mock` | — | без серійки, фейкові дані |
| `--passive` | — | пасивний режим: слухає трафік інвертора, не передає (несумісний з `--mock`) |
| `--list` | — | список портів і вийти |
| `--selftest` | — | самоперевірка CRC/парсингу і вийти |

## CSV-лог

Кнопка **Старт** на сторінці → файл `bms_monitor_<дата_час>.csv` у поточній
папці (де запущений скрипт). Формат: `ts, addr, rNN…` — сирі регістри з міткою
часу; активний режим = 39 регістрів свого пака, **пасивний = 28 регістрів
усіх паків, які бачить інвертор** (рядок на кожен пак, колонка `addr`).
Кнопка **Стоп** — припиняє запис (сам скрипт продовжує працювати). Статус:
назва файлу і кількість рядків видно у блоці «CSV-лог».

Логи `bms_monitor_*.csv` варто додати в `.gitignore` (не комітити).

## Правила безпеки (обов'язково)

1. **Тільки читання.** Додаток шле виключно `FC03` (читання), нічого не пише в
   BMS. Це свідомо: на шині поруч пастка `G5RC` (старий COM-Box приймав кадри
   оновлення прошивки), а запис конфігурації пака може зламати роботу.
2. **Не підключати паралельно з опитом коробки** (або інвертором): два master'и
   на шині = колізії кадрів. Як і з FT232-тапом: активний режим працює лише
   коли коробка/інвертор не опитують. **При живій системі — `--passive`**
   (жодного байта на шину, колізій нема; випробовано 22.10 при активному
   інверторі: стабільний ONLINE, бачить 0x01/0x02).
3. **Другий RS485-тап**: USB-UART під'єднується до роз'єму RS485 **пака**
   (паралельно ланцюгу батарей), бод 9600.
4. Після сесії — від'єднати апаратуру.

## Технічні деталі

- **Опит:** один запит `addr 03 00 00 00 27` + CRC16 Modbus; відповідь 83 байти
  (bytecount 78) → 39 регістрів. Інтервал — 0.35 с (рекомендований BMS —
  300 мс). Таймаут відповіді 1 с; при помилці порт закривається і
  перепідключається сам (сторінка показує OFFLINE + причину).
- **Парсинг** (за документом «MODBUS Protocol between UPS(SMPS) and BMS
  V01.01» + звірка зі скрінами BMS_TOOLS 10.10 та логами 17–22.10):
  - reg 0 = напруга ×10 мВ; reg 1 = струм ×10 мА,знак (0…32767 = заряд,
    від'ємний = розряд);
  - reg 2–16 = 15 комірок мВ; reg 18/19/20 = темп PCB/Avg/Max;
  - reg 21 = Cap Remaining (**А·ч** — одиницю підтверджено UI BMS_TOOLS:
    «SOC 31 % / Remain 31 Ah» при Cap 100 Ah), reg 22 = Max charging Current;
    reg 23 = SOH, reg 24 = SOC (**%**; у прошивці box SOC читається з 21 —
    відкрите питання до польової звірки);
  - reg 25 = Status: **енум у нижньому байті** (0 Standby, 1 Charging,
    2 Discharging, 4 Protect, 8 Charging Lmt) + нагрів `0x8000`;
  - reg 26 = Warning (14 біт), reg 27 = Protection (15 біт: `0x2000` =
    Discharge SC, `0x4000` = Reverse), reg 28 = Error Code (4 біти);
  - reg 29/30 = цикли, **ULONG hi-first** (`(r29<<16)|r30` — BMS_TOOLS
    показує `CyclesNum=1`); reg 31/32 = Full Capacity **hi-first, мА·с**
    (= А·ч×3600; 360 000 000 = 100.0 А·ч); reg 33–35 = 6 байтів сенсорів:
    Temp01–04 + 2 резервних нулі;
  - reg 36 = к-сть комірок, 37 = номінал ×0.1 А·ч, 38 = Cell Balance Status.
- **Структура коду:** `BmsBus` (фоновий потік опиту + стан під lock) →
  `Handler` (HTTP: `/`, `/api/data` GET, `/api/log` POST) →
  `ThreadingHTTPServer` на 127.0.0.1. UI — один HTML-рядок
  (змінна `HTML`), vanilla JS, оновлення `/api/data` кожну с.
  **Пасивний режим:** `parse_bus()` витягує FC03-кадри з потоку (запити
  len=8, відповіді `bytecount+5`, CRC-валідація, ресинк по 1 байту на смітті);
  тиша >0.15 с скидає неповний буфер; кадр свого `--addr` старший за 15 с
  (інвертор сканує 0x01–0x10 за ~10.5 с) → OFFLINE «немає кадрів».
- **Самоперевірка** `--selftest`: вектор CRC `01 03 00 00 00 27 → 05 D0`,
  живий вектор BMS_TOOLS `10 03 00 00 00 27 → 06 91`, парсинг напруги/струму/
  комірок, біт статусу + офлайн-перевірки від 22.10: енум статусу з нагрівом,
  цикли hi-first (=1), Full Capacity (100.0 А·ч), Temp01–04, біти
  Protection (Discharge SC / Reverse) і Warning (Float stopped) + пасивний
  парсер (`parse_bus`: запит/відповідь із сміття, частковий декод 28 регістрів
  із `None` для позавіконних полів).

## Плани (v2/v3)

- **v2 — Parameter read:** читання таблиці порогів (Cell/Pack OV/UV,
  OC з таймерами, Balance Vol/Diff — регістри розшифровано 21.10).
- **v3 — Control:** кнопки Charge MOSFET Open / Sleep / Float / Limit Charging
  (як у BMS Control) — **після** снифу ПЗ BMS Tools на Windows, бо публічний
  V01.01 адрес керування не містить (див. `IDEAS_BRAINSTORM.md`, розділ про
  скріншоти BMS_TOOLS). Запис — спершу тільки на від'єднаному паку, з обережністю
  (пароль, Restore Factory Data не чіпати).
